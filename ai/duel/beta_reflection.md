## 初始版本 beta_v1_combined_muster

版本只依据公开接口、公共执行层和 `data/rules.json` 设计，未读取 Alpha 源码、历史、冻结副本、私有思考或日志；没有自行运行对局。

策略使用公共 v7 的采矿、解堵、施工、正常支付和生产执行层，自行决定战术。它按己方存活兵力、受损后价值、可见兵种、靠近基地/矿车的威胁切换集结、防守与进攻。第一支部队以九个单位及约 1900 现存价值为出击门槛；150 秒后允许六个单位出击。受到压倒性基地威胁或进攻主力严重损失则重新集结。

步兵采用反装甲兵、机枪手和射手混合，根据可见装甲/步兵比调整。工厂优先坦克，辅以侦察车；科技可用后引入火炮。安全且已形成五人部队时允许第二炼矿厂；十二人、双炼矿厂时才预留科技，十八人且有资金时才预留航空。塔只在可见基地压力下考虑，避免闲时抽走前线资金。

显式命令由观察决定：近距离按本单位武器适性选择当前可见目标，优先敌军和受伤目标；其余部队按阶段集结、前进或回援。已正确执行的命令不每次重发，避让中的单位保留公共交通处理。对不可见目标只使用已观察建筑的位置作为移动目标。

采集器版本 `beta_recorder_v1_economy_front` 记录资金/累计统计及差分、工厂兵营队列、己方军力和最前位置、受伤及消失实体、矿车货物/位移/连续无进展时间以及矿车全部相关等待、避让、路径与卸矿诊断。可见敌军只记录公开兵种数量。正式胜负和原始证据由主 agent 保存。

初版待四场换边正式记录验证。重点观察：集结门槛是否延误，昂贵步兵是否挤压坦克，第二矿厂是否提高净收入，局部集火是否造成追击/交通问题。只有主 agent 判定整轮败者后才据本方 review 修订决策源码。根据主 agent 转达的最新用户授权，采集器允许在轮次之间丰富，但同轮冻结，初版完成后仍停止修改等通知。

策略和采集器均已通过 Godot 4.6.2 `--check-only` 语法检查。未启动完整对局。

3. 原策略撤退阶段仍先执行近距离集火，导致部分前线单位不及时服从重新集结；并且隐去敌军一瞬间即可把基地压力判断清零。这是代码与本方命令记录相符的控制缺口。

右侧终局累计低电 329.23 秒，后 285.53 秒从 779.7 秒电站被毁后开始。此前 735.5/745.7 秒两炼矿厂被毁，765.5 秒总部被毁；因此不能把这段长期低电视为最初失败根因。右侧到 400 秒单位交换价值约相等（己损 5049、敌损 5058），500 秒已经己损 9368、敌损 6426，700 秒己方作战单位只剩一辆侦察车；劣势形成早于基地大规模倒塌。

- 工厂完工后关闭共享采购，仍复用公共矿车调度、解堵、订单放置和普通建造/生产命令。按观察中的资金、已完工角色、生产队列和存活单位自行安排采购，保留首辆矿车/坦克优先，步兵屏幕不足时优先补充步兵。七人后先为扩矿补电，九人后才为第二炼矿厂储蓄；不再在五人时同时停掉两条生产线。

- 至少六名步兵、十二人/足够价值才初次出击；230 秒后允许十人队伍。推进目标依据己方步兵沿进攻方向的位置中位数逐步前移，射手和侦察车稍后，避免所有单位速度不同却追逐同一遥远终点。局部可见敌军显著占优或主力损失过半时，先执行撤退再考虑开火。基地威胁观察保留八秒缓冲。

## 第 4 轮：Beta v2 0:4；第 2 次败者修订至 v3
