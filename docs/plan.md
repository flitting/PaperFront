# 纸片沙盘 RTS：成品约束与首轮开发任务书 v1.0

> 当前视觉与坦克规则以用户 2026-10-01 的 [立体化升级要求](upgrade_3d.md) 为准：车辆、建筑和主要环境采用简化实体模型，炮塔独立旋转，坦克支持移动射击，使用暖色动态光影与 AO。本文保留原任务书记录；其中纸片车辆/建筑、面向镜头建筑及坦克停稳开火条款已被新要求覆盖。经济、胜负、地图通行及独立单位等未冲突要求继续适用。

## 1. 项目身份与最终目标

开发一款全新的、独立的桌面即时战略游戏，使用 Godot，主要开发语言为 GDScript。它与《Last Known Position》没有任何关系，不继承其代码架构、旅级指挥、小队模拟、通信、情报延迟、补给或士气系统。

游戏采用经典基地经营与战争对抗循环：采矿取得资金，发展电力和基地，建造生产设施，生产独立单位，组织进攻，摧毁敌方全部建筑。玩法参考《红色警戒》式经典 RTS 的基本组织方式，但不复制其名称、素材、界面、声音或具体阵营设定。

最终成品应像一座真正能游玩的手工纸片战争沙盘：有高低层级的牛皮纸地面，竖立的手绘纸片士兵、坦克、车辆、建筑和树木；镜头可以绕战场旋转，纸片具有可见的薄边，单位的转向、交战和死亡都能清楚辨认。它不是仅能截图的静态场景，也不是普通立体模型套纸张材质。

本文是成品行为与效果约束，不强制某种节点树、寻路算法或目录架构。工程实现可以选择，但不得以实现方便为由改变玩家可观察到的规则。本文优先于此前概念图和旧讨论中的冲突版本。阵营工作名与数值是本版原型默认值，尚未经过平衡测试，可以后续替换；核心规则不能静默修改。

## 2. 模式与范围

最终首发范围是一名玩家对一名电脑的遭遇战，包含两个真正不同的阵营。玩家可选择任一阵营，电脑使用相同的经济、建造、生产、战斗和胜负规则。

默认对局时长目标约 20 分钟，不设 20 分钟强制终局。全部操作实时进行，没有战术暂停、暂停下令或游戏倍速。打开菜单和保存不提供暂停下令机会；应用失去焦点时不主动暂停规则模拟，但不保证操作系统休眠期间继续运行。

支持对局存档与读取。不制作战役、剧情、多人与联网模式，不面向手机或网页平台。目标桌面平台为 Linux、Windows、macOS，先完成 Linux 验证。

不加入战争迷雾、侦察情报、视线遮挡、随机命中率、士气、压制、弹药、补给线、载员、航空、海军或复杂装甲模型。后续扩展不得提前成为首轮工程的负担。

## 3. 核心美术与纸片构造

### 3.1 整体风格

采用暖色牛皮纸、奶油色纸张、较粗的深色手绘轮廓、轻微不规则剪裁边缘和简化色块。红蓝等阵营强调色用于标志、制服局部、选择反馈和界面，不把整张地图染成高饱和色。

地面、道路、河流、高地、建筑、树木、单位、弹着和 UI 必须属于同一种纸艺语言。建筑不能是常规三维房屋，坦克不能是立体低模坦克，树木不能混用写实或通用低模资产。允许在一张平面插画里画出屋顶、履带或侧墙，但这些透视细节仍然只是纸上的绘画。

战场应有明确的轮廓、地面接触关系和留白。保留温暖的桌面沙盘氛围，但不强制制作房间或窗户背景；地图应占据主要画面。实际游玩不使用明显景深虚化，不让远处单位难以辨认。

概念图用于风格参考，不把图中七八座建筑、二十个单位或旧资源计数器当作游戏数量上限，也不沿用图中不符合本规范的立体纸模型。

### 3.2 纸片本体

所有存活单位、建筑及主要立牌装饰，都是垂直于地面的薄纸板。卡片必须有轻微可见的厚度和轮廓边缘，侧看时能够看到薄边，而不是完全消失。允许接近侧面时明显变窄，不为保持正面宽度而偷偷夹紧单位角度。

纸片剪裁应围绕对象轮廓，不能让每个对象都成为带大片矩形底色的广告牌。正背面复用同一套插画，不要求制作多方向或专门的背面资产。背面不能因剔除变成不可见。

厚度、贴图镜像、逻辑朝向、地面碰撞和选择区域是不同概念。不得把纸片侧面变窄当作单位占地或受击范围变小，也不得因切换动画卡片而改变单位寻路半径。

### 3.3 建筑与装饰的朝向

建筑、树木、岩石、山形立牌等没有战斗朝向的卡片，绕竖直轴保持面向当前观察方向。它们仍然竖直，不向下倾斜去完全贴合镜头平面。

镜头转动可以改变它们的显示角度，但不能改变建筑占地、门口、生产出口、通行阻挡、建造范围或攻击规则。桥梁的桥面、道路、坡道和高地几何固定在世界中；其装饰立牌可以遵守面向观察方向的显示规则。

单位不采用这种随镜头转动的朝向方式。

### 3.4 阴影与动画

使用简单、稳定的接地假影，例如地面暗色贴片或低成本简化轮廓阴影。无需实时复杂阴影、全局光照、镜面反射和电影级后处理。阴影不参与任何玩法结算。

各单位至少有待命、移动、攻击（有武器者）、受击和死亡的不同纸片形态。不能仅靠同一张静态图改变颜色来代替全部状态。行走有轻微摆动，开火有后坐或形态变化及枪口反馈，受击有清楚但短促的反馈，死亡有纸片倒下、破损或消散效果。

受击反馈默认不造成硬直，不中断命令或凭空重置攻击冷却。死亡立即结束该实体的活动能力，残留动画不能继续碰撞、攻击或计入存活建筑。短暂死亡动画可以打破竖直姿态要求。

## 4. 镜头、世界朝向与 80°镜像规则

采用透视相机，默认约 45°俯视，保留近大远小。支持平移、滚轮缩放和绕竖直轴旋转观察方向。首版俯角固定约 45°，不需要自由翻转或地下视角。

单位朝向使用一个固定世界水平坐标基准：以默认相机的水平朝向建立初始参考，然后保持不变。相机当前旋转角度、俯角和位置都不能进入单位镜像判定。

单位的逻辑水平角记为相对于该固定基准的 α，归一化到 -180°至 180°。本版镜像状态以 |α| > 80°为触发条件；|α| ≤ 80°使用未镜像状态。转向必须平滑，镜像不改变真实位置、命令、目标、碰撞和射击方向。

薄片实际朝向必须随单位的世界转向变化，而不是始终向镜头展示完整正面。实现跨面显示时，可以组合等价的纸片平面朝向、正背面显示与贴图镜像，确保图案中的车头、炮口与逻辑朝向一致；不得简单翻转整套实体坐标，造成枪口和碰撞方向反转。

镜头环绕时，单位可以呈现正面、侧面或背面，但其世界朝向和镜像状态必须保持不变。不得以“从当前镜头看起来更好”为由重新计算单位面向。

迷你地图必须能显示朝向参考线及 α，并检查 0°、±79°、±80°、±81°、±90°、±135°、180°等角度。80°边界、前后跨面和镜头环绕均不得造成单位突然反向移动、炮口反向或文字镜像。

## 5. 实体、操作与空间占地

一张单位纸片对应一个可独立选择、独立移动、独立战斗结算的单位。没有小队、连、班或不可见的下属士兵模拟。

256 是性能参考规模，不是人口上限、生产上限或实体硬限制。移动单位和建筑分别统计；树木、道路和纸艺装饰不计入该参考数量。不得显示“256 人口上限”或达到 256 就禁止生产。

移动单位采用稳定的地面占地范围，建筑采用稳定的网格占地。显示纸片、点击区域和实际占地允许不同，以保证侧身时仍容易选择。普通移动单位之间不能持续重叠或互相穿过，必须有基本绕行、让路和堵塞处理；不要求复杂交通仿真、挤压物理或真实车辆动力学。

车辆有转向过程，可原地调整方向，不瞬间掉头。普通移动以行进方向为车体方向，不需要坦克横移或复杂倒车行为。选择或拖动不直接搬运已部署单位。

基础交互采用左键点选、拖框多选，右键移动或对敌方目标攻击，Shift 追加命令，数字编队，A 攻击移动，S 停止；支持生产建筑集结点。地图点击必须正确换算到当前相机下的地面位置，不能因旋转镜头导致目的地偏移。

多单位移动时应分配附近可站立的位置，而不是让所有单位争抢完全相同的一个坐标。无路可达时停止无效抖动，给出失败反馈，不瞬移或穿越障碍。

## 6. 地形、高度与桥梁

地图地表有真实高低层级，首版可采用四层高度，默认高度差为两个地图单位。单位只能通过合法坡道切换高度；不可直接爬上悬崖或跨越水面。

树木、岩石、悬崖、水体等只承担装饰及预先定义的通行阻挡。不计算视线、掩体、隐蔽、射界遮挡或高地攻击优势。射程按水平距离计算，高地不增加攻击或防御；隔着建筑、树林和高地攻击射程内的目标是本版明确规则，不是错误。

建筑占地必须处于同一可建造高度层，不能悬空、跨悬崖、跨坡道或跨桥面。首版不做同一水平坐标存在上下两条均可通行道路的复杂立交。

桥梁是可攻击、可破坏、可修复的中立通路实体，不属于任何阵营的胜负建筑。桥面禁止建造建筑。

桥梁被摧毁的同一结算时刻，实际位于桥面上的全部单位立即死亡，不区分敌我；未上桥的单位停止进入并重新寻路。不把桥上单位传送到岸边，不模拟落水求生。

工程师在可达桥头修复桥梁，消耗资金和时间。只能修原有桥位，不能自由架桥。工程师离开或死亡时修复暂停，已完成进度保留；修复完成后恢复通行。桥梁残骸保留修复入口，普通建筑残骸短暂显示后清除阻挡。

随机地图及默认手工对战图至少有一条不依赖可破坏桥梁的陆路，避免断桥导致双方永远无法结束对局。

## 7. 经济、电力、建造和胜负

### 7.1 开局与采矿

双方以一座已展开、已完成的总部和相同初始资金开局。开局没有额外部队或其他建筑。不制作基地车展开流程。

单一矿石、单一货币；矿车自动采矿，装满后寻找可达的己方精炼厂交付，再返回矿区。被摧毁矿车的未交付货物损失；精炼厂被毁时寻找其他可达精炼厂，没有就保留货物等待。

矿石只在原有矿点内再生，有容量上限，不向建筑、道路或其他地块扩散。枯竭时保留矿点身份，后续继续再生。矿车优先寻找可用矿点，无矿可采时等待，不死循环振荡。

每座精炼厂完成时附带一辆对应阵营矿车，只触发一次；出口被堵时等待合法生成位置。读档不能重复赠送矿车。单位不能通过出售获利，建筑可出售。

### 7.2 电力

阵营电力按完成建筑的产能和消耗统一结算，不需要电线、电网连接或输电距离。

电力不足时，建筑建造和单位生产速度降为正常的 50%，防御塔停机；现有移动单位、采矿、资金交付和普通命令仍可工作。满足正常建造条件时，缺电本身不得阻止建造发电站恢复供电，不形成仅因缺电而永久无法自救的规则死锁。

### 7.3 建造与生产

全局一条建筑建造队列。支付费用并完成倒计时后，建筑进入“就绪”，玩家在建造栏再次选择它，在合法位置确认放置。只有一个活动建造项或待放置就绪项；就绪建筑未放置或取消前，不开始下一座建筑。

放置后立即占地、可被攻击，并计为存活建筑；播放默认 1.5 秒建成动画，完成后才供电、生产、攻击或提供扩建功能。非法位置不得扣第二次钱、丢失就绪状态或生成部分建筑。

建造范围由己方已完成的指定建筑提供，默认总部、经济建筑、生产建筑和专属科技建筑均可扩展，防御塔不能单独扩展范围。默认扩建半径 12 个地图单位。

必须有存活且已完成的总部，才能推进建筑队列或放置就绪建筑。总部被毁但其他建筑仍存活时不立即失败，已有生产建筑仍可工作；不免费重建总部或生成基地车。已有总部时可以建造额外总部。

每座单位生产建筑拥有独立 FIFO 队列。订单入队支付费用；出口堵塞时完成单位等待，不能重叠出生或瞬移到任意地图位置。多个生产建筑可并行工作。

取消未开始订单全额退款，取消进行中订单按尚未完成的比例退款；就绪建筑已完成全部进度，取消不退款，必须有提示。生产建筑被毁时，其队列按同一取消退款规则处理；已完成但因堵门未部署的产物损失。

出售建筑返还配置比例的资金，默认 50%；出售最后一座建筑前需确认。修理己方建筑持续耗资恢复生命值，不是免费瞬间回满；首版可通过建筑修理操作执行，不要求派工程师修普通建筑。

### 7.4 胜负

一个阵营的全部已放置建筑被摧毁或售出即失败，包括总部、经济建筑、生产建筑、防御塔及仍在建成动画中的建筑。

移动单位、桥梁、装饰、建造栏里的就绪建筑均不能延续比赛。仅摧毁总部不等于胜利。双方在同一伤害结算批次中建筑同时归零时为平局。

结算后停止接受战斗命令，展示胜负与基本统计，允许返回菜单或重新开始。20 分钟不是自动终止条件。

## 8. 战斗、炮弹与碾压

### 8.1 基础规则

基本战斗参数为生命值、伤害、射程、攻击间隔、移动速度、转向速度及必要的炮弹参数。无随机命中检定、暴击、装甲穿透、部位损伤或属性克制表。兵种差异通过生命、伤害、射速、范围、机动性、占地和价格体现。

坦克必须停稳并将整张车体纸片转向目标后才能开火；不允许移动射击，也不允许炮塔独立旋转。首轮其他地面武装单位同样采用停稳开火，以保持规则简单。开火角度容差为配置项，默认 15°。

普通移动优先执行行军，不因路过敌人自行停下交战。对目标的攻击命令允许接近和追击，到达射程后停止并开火；目标死亡后结束该指定攻击，转入原地待命。攻击移动沿目的地方向推进，遭遇可交战敌人时停下攻击，战斗结束后继续原路线。原地待命自动攻击射程内敌人，不远距离追出基地。

S 停止取消当前及排队命令。无法到达有效射击位置时不得穿墙或持续高速重寻路；给出可辨认的等待或失败状态。

### 8.2 固定落点炮弹

炮弹发射时记录目标当时的世界落点，之后飞向该固定位置，不追踪目标，不预测未来位置。炮弹有可见飞行时间和简单弧线或曳光表现。

落地时检查爆炸范围与附近实体的实际占地是否相交，命中哪些实体就伤害哪些实体。原目标可以移出范围躲开；其他单位进入落点会受伤，包括友军和己方建筑。范围内所有可受伤实体分别结算一次伤害，默认无距离衰减。

炮弹不与途中树木、建筑或单位做弹道阻挡碰撞，只在落点结算。攻击者死亡或原目标提前死亡都不取消已经发射的炮弹。炮弹不能在发射时预先扣血，动画结束后再补做同一次伤害。

普通步兵机枪类武器可采用对选定敌人的即时命中，附带枪口和曳光反馈；爆炸类武器统一采用固定落点及友军误伤规则，不使用随机命中率。

伤害和攻击间隔由游戏规则控制，不依赖动画播放帧数。改变贴图或播放速度不能改变 DPS，也不能让一次开火多次结算。

### 8.3 碾压

只有配置了碾压能力的车辆可以碾压，首版为坦克和重型突击车，矿车默认不具备碾压能力。普通步兵、反装甲步兵、工程师和爆破手均可被碾压。

车辆与敌方可碾压步兵发生有效地面接触时，该步兵立即死亡；己方步兵仍是必须绕行或等待的实体，绝不可误碾或直接穿过。

普通攻击步兵优先使用武器；执行移动、追击时路径经过敌方步兵则可发生碾压，不擅自远距离转为追人碾压。不能把碾压写成所有车辆忽略所有步兵碰撞。

## 9. 两个阵营与第一版独立数值

工作名采用“铆钉联队 / Rivet”和“游隼联队 / Kestrel”。铆钉偏厚重、耐久、慢速和范围火力，建筑轮廓偏宽厚工业构造；游隼偏轻便、机动、较低成本和快速交战，建筑轮廓偏轻型工棚及框架构造。两者都使用纸片画风，不引入写实模型。

阵营身份不能只靠红蓝换色。核心兵种功能可以对应，但建筑插画、命名、数值和专属兵种必须不同。阵营与玩家颜色分开配置，另用标志形状区分双方。

以下都是未经平衡测试的原型起点，不承诺首次运行就自然形成 20 分钟均势；所有值必须来自独立配置。

## 10. 地图、电脑与测试入口

必须有三类地图，共用相同实体、命令、经济和战斗规则，不为测试另写一套简化游戏。

极小测试地图默认约 48×48 格，包含两个阵营的测试对象、朝向标线、平地、坡道、高地、矿点、窄路和可破坏桥梁。通过调试入口快速重置场景、补充单位、查看碰撞和验证规则；这些作弊功能只在明确标记的开发模式生效。

手工验证关卡默认约 160×160 格，提供完整开局、双方矿区、至少一条陆路、多条进攻路线和扩张矿区，能够完成经营到胜负的完整遭遇战。开局每方至少两个等价近矿点，距离及可达条件接近。

随机地图默认同等规模，支持输入和显示随机种子。生成结果必须检查出生点平坦、建筑空间足够、矿区可达、双方基础资源接近、坡道连接合法、至少一条不可被断桥彻底切断的对抗通路。不合格结果自动重试或修复，不把不可完成地图交给玩家。

电脑最终必须能建立供电和采矿、建造生产设施、生产并集结部队、进攻与应对基地威胁，支持两个阵营的数据。电脑不额外获得资金、视野之外的特殊信息、免造价单位、加速生产或伤害奖励。地图无迷雾，双方都能知道公开场上信息。

首轮可先用简单规则脚本或可控制的敌方测试单位，不需要完整策略 AI；脚本仍必须经过真实费用、前置、生产队列和合法命令，不能用定时免费刷兵冒充公平 AI。最终成品必须能在无调试工具介入的情况下完成单人遭遇战。

## 11. UI、音效与可读性

界面采用与地图一致的纸板面板、手绘图标和清楚文字。顶部显示资金、电力供需、己方单位及建筑数量和时间；底部或侧栏显示建造、生产、队列和命令；提供小地图与选中对象信息。

小地图显示地形、双方单位与建筑、当前相机可视范围；不能只贴一张装饰图片。鼠标在 UI 上操作不得穿透成地面命令。建筑就绪、缺电、资金不足、出口堵塞、目标不可达和非法放置都要有明确反馈。

选中单位时，血条位于其纸片上方，并与单位纸片平行，随纸片世界转向变化，不单独始终正对镜头。卡片侧看时血条也允许变窄。贴图镜像不能把血条、数字或文字一起镜像。底部信息栏同时提供稳定可读的生命值。

建筑血条随建筑显示平面。选择圈、移动目标和路径反馈锚定地面；必要的选中轮廓不能改变视线或战斗规则。

基础声音包括选择、命令、开火、爆炸、采矿交付、生产完成、建筑落地、出售、低电提示及胜负。优先自制或使用授权范围明确的公开资源，记录来源、许可和署名要求。不直接截取其他商业游戏声音。音效可以分阶段完善，但最终不能只有背景音乐而缺少操作反馈。

## 12. 独立数据、存档与可调整性

单位、建筑、武器、经济、电力、前置关系、阵营内容和动画资源映射必须集中为可编辑的数据配置，在启动或新开对局时读取。第一版可采用 JSON 或同等清晰的数据格式，不强制使用某个数据库。

使用稳定内部 ID 关联内容，显示名称可替换。启动时验证重复 ID、缺失引用、非法价格、无效攻击间隔、遗漏动画和错误前置关系，输出具体位置的错误，不静默生成错误实体。

不得把同一个伤害或价格分别写死在 UI、生产代码和战斗代码里。界面、电脑和玩家必须读取同一份规则数据。调整纯数值不能要求修改单位脚本。

存档至少保存地图实际布局与种子、时间、阵营、资金、电力相关建筑状态、单位与建筑的位置和生命、朝向、命令队列、目标引用、攻击冷却、生产及就绪状态、矿车货物、矿点余量和再生进度、桥梁破坏及修复进度，以及在途炮弹及其固定落点、剩余飞行状态。

保存同一模拟时刻的一致快照，不把半个时刻的多个系统混在一起。读档不能重复产出、复制资金、消除在途炮弹、重置所有武器冷却、恢复已毁桥梁或丢失修复进度。

存档记录格式版本，并包含本局规则配置快照或可恢复的等价规则版本。新对局使用新数值，旧存档不因外部配置被修改而悄悄更换整套规则。读档不兼容时必须明确报错。

用户设置与存档使用可写的用户数据位置，不能依赖开发者工作目录或固定 Linux 绝对路径。

## 13. 性能、兼容性与工程边界

目标是用户现用 Linux 笔记本上，1920×1080 下正常交战稳定接近 60 FPS。优先验收机为 ThinkBook 14 G6 IMH，实测时记录实际 CPU、GPU、内存、驱动与构建方式，不猜测配置或在没有该设备实测时声称已经达标。

正式性能基准场景至少约 256 个移动单位与建筑合计的活动实体，例如 224 个移动单位加 32 座建筑，包含多组同时移动、寻路、交战、采矿和生产，另有正常密度装饰。额外提供 256 个移动单位加建筑的压力场景，分别报告数量，不混用统计口径。

同屏数十个单位是常态。不能以空地图 FPS、静态摆放 256 个图标或关闭实际战斗逻辑代替验收。不得为了帧率而停止屏外单位的正常经营与战斗模拟，也不能降低游戏时间流速伪装流畅。

树木虽不计入单位参考，仍有渲染和阻挡成本。限制不必要透明重叠、阴影、粒子和后处理，可简化远处装饰与效果，但不牺牲核心纸片风格、命中反馈或可读性。

报告平均帧率、明显卡顿、CPU/GPU 帧耗时及可获得的低帧或分位数指标。目标 60 FPS 对应约 16.7 毫秒帧预算；没有目标机测试时标为待验证。

Godot 版本在项目启动时选定、记录并保持一致。Linux 是首轮必测平台，代码、文件路径和输入不能写成 Linux 专用；Windows、macOS 是后续桌面验证目标。尚未实际构建或运行的平台不能标为通过。

不要预先加入 Rust 后端、复杂插件框架、多服务架构、联网同步或过度多线程设计。选择能够支持这些成品行为且易调试的简单实现；性能问题以测量为依据处理。

## 14. 首轮开发范围与交付顺序

先完成迷你地图的纸片表现验证，再进入手工地图的可玩闭环，最后扩展随机地图和完整 AI。后续阶段不是取消最终要求，而是避免首轮同时展开所有系统。

第一阶段必须在 Linux 可启动项目中展示：一致纸艺地面与对象、45°透视及镜头环绕、单位固定世界朝向、80°镜像、实际厚度、建筑面向观察方向、平行血条、不同动作卡片、选择移动、基本避让、坦克停稳开火、固定落点伤害、友军误伤、碾压、高低层及断桥。

第二阶段完成两个阵营的基础数据和不同视觉，接入真实采矿、电力、侧栏建造就绪、合法放置、出售、队列出兵、基础战斗和摧毁全部建筑的胜负。手工图中应能从总部开局一直玩到结束，不依赖调试刷钱或刷单位。

第三阶段补齐存读档一致性、随机地图验证、公平电脑、完整 UI 与声音，执行性能和桌面兼容性测试。存档所需的稳定 ID 与状态设计从前期保留，不能等最后才发现无法保存对局。

首轮初步交付以第一阶段完成、第二阶段形成最小真实闭环为目标。完整 AI、随机地图细化和最终音效可以明确列为后续；不能因此把这次交付只做成静态场景或无经济规则的演示。

初期素材允许简化，但必须遵守纸片画风、真实旋转与厚度，不接受用普通立方体和胶囊占位后宣称核心视觉已完成。两阵营内容可逐项补齐，但第一轮结构不能只容纳一个阵营或依赖硬编码换色。

每次交付提供启动步骤、已完成与未完成项、关键规则测试结果、截图或录像以及实际测得的性能。无法运行的测试必须标明，不能声称通过。

## 15. 成品验收清单

| 场景 | 必须满足的结果 |
|---|---|
| 镜头旋转一整圈 | 建筑和装饰保持可见正面；单位的世界朝向和镜像状态不随镜头改变 |
| 单位跨越 80°边界 | 按固定世界基准切换镜像，位置、车头逻辑和命令不反向 |
| 从侧面观察单位 | 可见薄边，允许变窄；碰撞、命中与选择不随显示宽度缩小 |
| 单位被选中并转向 | 血条与卡片平行，文字不因镜像反转 |
| 坦克正在行驶 | 不发射；需要停稳、转向并满足冷却和射程后才开火 |
| 目标在炮弹飞行中离开 | 炮弹仍落在原地点，原目标可躲开 |
| 敌人或友军进入原落点 | 按当前占地受范围伤害，不仅检查原目标 |
| 发射者提前死亡 | 已发射炮弹继续飞行和结算 |
| 坦克接近己方步兵 | 绕行或等待，不碾压、不穿过 |
| 坦克实际驶过敌方步兵 | 可发生碾压，普通车辆不能全部默认具备此能力 |
| 非法建筑放置 | 不生成、不额外扣款、不丢失就绪建筑 |
| 建筑落地尚未完成动画 | 已占地且可受伤，但尚未生产、供电或攻击 |
| 生产出口被堵 | 等待合法部署，不穿墙或叠放出生 |
| 电力被切断 | 减速和停塔正确，已有部队和采矿仍工作，并能恢复供电 |
| 断桥 | 桥上双方单位死亡、桥面断路；岸上单位重新寻路 |
| 修桥 | 消耗和进度正确，中断可续，完成才恢复通行 |
| 仅总部被毁 | 其他建筑仍存活则继续比赛 |
| 最后一座建筑消失 | 正确结算失败，即使仍有坦克、矿车或就绪建筑 |
| 保存后读取正在交战的对局 | 资金、队列、命令、冷却、炮弹、矿石和桥梁状态延续，无重复产出 |
| 两阵营分别进行完整对局 | 建筑、数值、特色单位不同，且都能独立建立经济和结束比赛 |
