# 视觉目标与固定对比基准

日期：2026-10-01。参考分析已完成，Golden Visual Test Scene G0 已实现并冻结。两次独立启动的 PNG 字节完全一致；当前 `--showcase` 仍只作动态观测，不作为对比基准。最新接续命令、用户偏好与有效版本见 [art_iteration.md](art_iteration.md)。以下G0建立规格保留为历史，不把它升格为美术目标。

目标是 **hand-painted tabletop diorama / chunky toy-like 3D**：有真实厚度和空间关系的手绘桌面模型，保持默认 RTS 视角下的辨识度与操作空间。每轮选一组影响最大的相关问题，用实际运行截图判断方向，允许必要联动。正常RTS游玩视角是主验收，资产场/特写仅诊断，压力场仅辅助。

## 各维度的可观察目标

| 维度 | 参考图中的特征 | 游戏中的设计目标与可读性约束 |
| --- | --- | --- |
| 车辆比例 | 车身低、宽、长；履带/轮子占外轮廓显著部分；炮塔比车身小，炮管清楚；重车靠体块区分 | 保持真实 3D 车体与独立炮塔。优先让履带、车体、炮塔三层在默认视角分开，避免车体变成高盒子或炮塔吞没车身。当前车辆整体比例已有基础，先通过固定场景确认，不预设全部重做 |
| 建筑比例与 silhouette | 厚墙、明确斜屋顶和入口；HQ、烟囱电站、工厂、塔架用大轮廓识别；建筑明显大于车辆 | 建筑具有封闭体积、侧墙、屋顶厚度。功能识别先靠大形，再靠徽记；工厂入口、电站烟囱、塔架应在整图尺寸可读，不依赖微小窗饰 |
| 全局 palette | 暖褐纸土是主体，深褐缝隙和深绿森林是暗部，蓝水/矿物与蓝红军形成冷暖跳色 | 暖土保留，但不让整屏只有相近浅黄色。用林地、河谷、土斑和阴影组织色块；阵营颜色在正常视角清楚，不把所有大面刷成同一颜色 |
| 阵营色分布 | 大部分模型仍是棕纸；蓝红集中在粗边线、门框、旗帜、徽记和局部涂装；屋顶颜色有纸底和磨损变化 | 保持蓝红识别，同时让纸板主体占主要面积。减少干净、整块饱和屋顶的印象；先独立比较色彩覆盖面积，再讨论纹理与描线，避免一次改三个维度 |
| 材质 | 粗深墨线、纸边厚度、可见的斑驳涂色、土斑/碎屑；大明暗块和中等尺度笔触比细噪声更显眼 | 哑光纸土、较粗且不完全机械的线条；笔触和色块在正常画幅可见。细纹理服从轮廓与道路，避免规则织纹、塑料压纹、高光金属和写实迷彩 |
| 灯光与空间 | 亮面偏暖、背光面较深；墙角、林底、轮下有接触暗部；桥拱和崖壁形成深度 | 暖主光与适当填充、接触阴影及适量 AO 是实现假设。保留受光/背光差异，不用泛黄后处理代替层次；林内与红蓝单位的暗面仍可辨 |
| 镜头 | 能看到屋顶、侧墙、前景崖壁与桥拱；中景交战清楚，近远景较虚，有桌面微缩感 | 低于原 45° 的视角作为起点；只在建立基准时校准一次。优先让两军、桥和连接路径进入可见战区。景深是后续可选探索，不能模糊部队、血条、目标或选取反馈 |
| 地形 | 大小错落的折边/圆转平台，崖顶不规则；粗细纵裂、局部层理和岸脚石；斜向/S 形河谷联系前后景 | 地形有大、中、小三种尺度变化，避免等间距柱列和长直台阶。保持合法通路与战区留白；地形外观修改不能制造视觉可走、规则不可走的误导 |
| 环境 props | 高矮松林成簇，林缘有孤树/小丛；断墙、遗迹、木栅栏、箱群、石块围绕基地、道路转折和岸边分布 | 装饰有位置关系与成组节奏，不做均匀撒点。低矮细节补充空地，明确区分密林、边缘与通道；避免用挡住部队的大树解决空旷感 |
| 构图与战斗 | 两侧基地、中间路径与交战点构成连续关系；明亮爆炸/弹道是局部焦点；前后树林/废墟框景 | 先读基地—路线—桥—战区，再读单个模型。特效短暂、集中，有清楚命中位置；不能成为掩盖地形或遮挡敌我的大烟幕 |

图像不能证明准确俯角、FOV、真实尺寸比、灯光数量或 AO 算法。上述镜头/灯光机制属于实现推断，后续数值必须通过固定场景截图验证；不把概念图透视下的像素比例直接当作模型尺寸。

## Golden Visual Test Scene：G0 固定规格

沿用G0的可复现中期状态，增加普通RTS镜头和正常HUD作为主验收；G0宽视角用于整体辅助比较。模型画廊、自由特写与压力场各有用途，不能代替正常游玩画面。

### 固定内容与构图

- 地图起点：现有 handmade 地图，seed `73026`，保留中央河谷、完整桥梁、高地/坡道、森林、石块与蓝矿。首次建立时保存完整地形、障碍和 props 的位置/变体清单，不能只依赖 seed 在修改生成器后仍得到相同地景。
- 阵营：左侧 Rivet 蓝军，右侧 Kestrel 红军，AI 关闭。以现有 showcase 的基地和部队配方为起点：前线每方 HQ、电站、兵营、精炼厂、工厂、塔各一座，另各保留原始 HQ（合计 14 座建筑）；各 12 个单位（合计 24 个），双方有普通坦克、采矿车、步兵与工程兵，蓝方另有现有重突车，红方另有现有爆破兵，不新增兵种。
- 在两个基地、桥头与一组前景车辆之间保留可读道路。车辆至少包含正侧可辨的姿态，以及车体朝向和炮塔朝向不同的样本。保存各实体的 ID、spec、坐标、高度、车体/炮塔朝向、HP、动画状态和选择状态；以后不再每次用 `standable_near` 重新寻找位置。
- 全部建筑完成、桥未受损、矿量固定；两辆蓝军普通坦克固定选中。建造栏固定在同一页和滚动位置，保留一张固定进度的卡片，避免界面变化干扰画面。
- 保持完整游戏 HUD。校准时让两军主要建筑、代表车辆、桥和连接道路落入 HUD 外的战区；不要为拍摄缩小模型、藏起右军或关闭侧栏。

### 摄像机、画幅与光照

输出 `1920×1080`，16:9，窗口模式，UI 逻辑画幅 `1600×900`。使用实际 Forward+ 渲染、MSAA 2×、方向光阴影 2048 和当前中等 SSAO。关闭镜头输入、边缘移动、自动追踪和读取个人镜头设置。

已通过实际截图校准并冻结摄像机：focus `(80,102)`、pitch `30°`、yaw `0.32 rad`、distance `54`、h_offset `9.10`，FOV `42°`、near `0.2`、far `500`。预检曾使用 h_offset `8.10`，最终仅将画面左移约 1m，为右侧电站留出空间，保持车辆与步兵可读尺寸。此构图校准用于建立历史基准，不计作美术改进。后续通常固定；若地景或取景本身是主要差距，可显式调整并保留前后图，不能靠裁问题或加模糊制造进步。v12右侧独立战场视口后实际 h_offset 已为0，以实图JSON为准。

构图预检：主体不进入右侧建造栏；1920 画幅中右边界尽量小于 `1543 px`，下边界小于 `838 px`，并避开左下小地图。若更宽镜头令单位过小，应调整 fixture 的合法布局后重新预检，而不是接受不可读的基准。

G0 光照初始采用当前参数，随后只有“灯光”轮次可修改：

### 固定时间与截图流程

主对比帧是静态 fixture：禁止实时 AI、移动、采矿和生产推进，仿真时间、订单进度、步兵动画、车辆摇晃/后坐力、水面/材质时钟全部固定。首次布置后将仿真 tick/time、实体和订单状态写入清单；主帧 visual time 与模型 clock 设为 `0`，无烟尘、弹道与死亡动画。不能用“运行 3 秒”代替确定帧。HUD 时间与诊断文本也固定，FPS/CPU 区域显示固定的 G0 标记，鼠标离开战区与卡片，菜单/提示/放置预览关闭。

先完成 `8` 个渲染暖机帧，不推进仿真与动画时间；第 8 帧等待 `frame_post_draw` 后保存真实 viewport PNG。再用可用的 Linux 截图工具获取固定窗口截图作为运行证据；桌面截图不能替代无窗口边框的主图。记录实际像素大小，不能后期缩放修图来制造一致画幅。

效果轮次使用同一 G0 的预设战斗时刻：保存固定命令、30 Hz tick、炮塔姿态、弹道与特效年龄；按固定步长同步仿真和视觉后冻结。前期主图保持无爆炸遮挡，后期可额外比较这一预设时刻，但不新增另一套地图或自由镜头基准。

入口已实现：`--golden-visual` 与 `--golden-capture <path>`；`--golden-hold` 保持窗口供截图工具取证，Esc 退出。固定清单为 [data/golden_visual_v1.json](../data/golden_visual_v1.json)，包含完整地形/实体状态与实际 props 位置、变体，启动不重新搜索实体位置。静态主帧为 tick `135`、simulation time `4.5s`、visual time `0`、建造进度 `30%`，两军共 14 座建筑与 24 个单位。

输出目录为 `artifacts/visual_iteration/g0/`，主图是 [g0_baseline.png](../artifacts/visual_iteration/g0/g0_baseline.png)，对应 [metadata](../artifacts/visual_iteration/g0/g0_baseline.json) 与 [运行日志](../artifacts/visual_iteration/g0/g0_baseline.log)。每轮另存 PNG 和元数据，不覆盖上一张。截图记录实际镜头、光照、渲染器、分辨率、固定时间和源码哈希。

自动运行并截图：

```bash
python3 tools/capture_golden.py --name next --views gameplay,g0 --output-dir artifacts/visual_iteration/next --baseline artifacts/visual_iteration/v14_ground
```

脚本启动实际 Godot 项目，进入 G0，核对新 PNG 的 1920×1080 尺寸、冻结时钟、fixture、镜头和光照。对比例图仍须打开实际 PNG 查看；条件一致不等于美术已经改善。灯光轮次会有意改变 lighting，应独立记录该维度，不使用禁止光照变化的默认 baseline 核对。

`--hold` 会保持实际窗口供 Linux 截图工具取证，Esc 后完成元数据核对。仅灯光轮次可使用 `--allow-lighting-change`，镜头、fixture、时间、选择和画幅仍必须匹配；其他轮次以最近保留版本的 JSON 为 baseline，继续核对光照与新增的渲染设置。v03 仅将方向光滤波质量从初始 `2` 改为 `4 / SOFT_HIGH`，未改主光、AO、shadow_blur、bias 或 TAA；初始基线图保留原样。v07 灯光轮次已保留主光 `#ffd3a0 / 1.4`、冷填充 `#b9cee1 / 0.22`，其余灯光/AO/投影参数不变。

可选 `--executable artifacts/linux/PaperFront.x86_64` 用同一流程核对导出的独立程序；此时不传项目 `--path`。

首次 G0 已重复启动并拍摄 [g0_repeat.png](../artifacts/visual_iteration/g0/g0_repeat.png)：对比条件一致，PNG 字节也完全一致（SHA-256 `fe1a229b7135c4e3431c1e91cec41ab2df88b9940d4a2ee05d62b3622cd6b9f5`）。Linux 原生截图工具另已捕获实际 G0 窗口；它包含窗口边框且按工具上限缩放，只作运行证据，1920×1080 viewport PNG 始终是主对比图。跨硬件不要求 PNG 字节一致，但不能出现布局或时刻漂移。

## 单维度迭代规则

1. 从原图和当前实图重新判断最大未解决差距，历史 [visual_gap.md](visual_gap.md) 供排除无效方法，写具体假设和本轮相关改动。比例/轮廓、palette、灯光、材质、地形/props、特效是检查顺序，不要求为已经基本合理的尺寸制造改动。
2. 冻结摄像机、画幅、fixture 状态，以及本轮之外的维度。地形轮次可改可见地形/装饰，但固定河桥位置、战区、实体锚点和合法通路；相关清单变化必须记录。
3. 自动启动实际游戏 → 进入 G0 → 固定状态 → 截图 → 查看。将两张参考图、G0 上一版、本轮图并列判断，不用“代码已实现”代替视觉结论。
4. 每轮写明哪些画面区域改善、哪些无改善或变差，以及单位/建筑/道路是否仍可读。只有截图支持才保留；若方向不理想，小步调整同一维度后重拍，必要时回退。
5. 当前只做启动、截图成功和受影响关键交互的最小验证。例如模型轮次检查炮塔，地形轮次检查相关通路，HUD 轮次检查滚轮。整体方向定稿后，再统一做细节、全面回归和性能整理。

整体方向的通过条件：默认画幅中车辆和建筑功能可辨，纸板主体与阵营标识协调，暖面/暗部/冷色有层次，地景不再以空白平面和重复柱列为主，手绘痕迹在正常尺寸可见，部队/桥/通路仍清楚。这个条件当前尚未达到。
