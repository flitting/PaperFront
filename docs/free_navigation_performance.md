# 自由寻路吞吐优化与复测

本轮解决大量地面单位同时下令时，后台任务排队过长、选中路径分批出现，以及悬崖和桥边路线难以实际执行的问题。游戏继续使用真实单位半径、任意角度路径和逐步运动碰撞；下令、建造、经济与游戏时间照常推进。

本文件记录实现、对照方法和结果。结果表使用修正 Debug 放置规则之后的同一场景；旧视觉测试已终止，各压力进程串行执行。较早诊断数据保留在 artifacts 中，不作为最终性能证据。

## 实现

### 后台提交与并行

`scripts/path_worker_pool.gd` 默认启动两个低优先级工作线程。每个线程独占自己的 A* 图、半径掩码、障碍索引和走廊缓存，读取不可变快照，不访问实时实体或渲染节点。

正常模拟每 tick 最多提交 32 条请求（最终调度参数），全局最多 32 条在途任务；每个工作线程的待收取任务最多 16 条。分派优先选择较少待处理任务的线程，锁竞争时尝试另一个线程，仍无法提交则保留模拟队列。主线程任务交换预算维持 750 μs，并使用非阻塞锁。以上限制约束任务交换，不是整个模拟 tick 的耗时上限。

旧版本每 tick 最多提交两条、最多两条在途，并在工作线程完成每条路径后额外等待 1 ms。新版去掉这段逐任务等待，通过低线程优先级和有界队列控制 CPU 竞争。同步规则测试仍使用独立的有限预算。

### 减少单条路线的重复工作

Debug 的 `standable_near` 同时检查完整预留半径与森林、矿区和悬崖碰撞。旧放置只查地块类型与实体间距，压力场景中会把四个半径 0.35 m 的单位放进被树木封闭的空腔；它们虽然站得下，但无法离开。按 Debug 原有 0.8 m 预留半径检查后会选择空腔外的落点。算法对照组采用相同的修正后布局。

`scripts/path_worker.gd` 保留 A* 提供绕行候选点，再对真实起点、真实终点和每条简化线段进行碰撞检查。

- **指数前视简化**：从近处开始，按 1、2、4、8 等距离探测可见候选点，首次失败后最多补充四次区间探测。原先从终点反向逐点扫描会在长悬崖、桥梁绕行中反复检查大量长线段。每条最终采用的线段仍经过完整检查；可见性并非单调，因此这项优化可能保留额外安全拐点，不能据此声称得到全局最短路。
- **沿线障碍桶**：障碍以 2 m 空间桶索引。短线段查询少量包围盒桶；长线段沿路径采样，并扩大查询范围以保守覆盖整个扫掠圆。固定单位半径下，访问桶数量随线段长度增长，避免长对角线按整个包围矩形面积枚举。硬障碍、车辆专用障碍和合并后的废墟索引共用同一份线段桶列表。
- **平地快速检查**：使用模拟提供的不可变平地掩码，确认周围 3×3 单元属于安全平地时省去重复的高度及边缘采样。岸线、坡道和高度变化仍进入详细检查；半径超过掩码适用范围的单位也执行详细检查。
- **边检查记忆**：同一半径和几何版本下保存已验证的图边，避免失败路线多次逐边重复扫掠。几何版本改变时清除这部分结果。

### 同目标区域的走廊复用

目的地按 8 m 区域分桶。同一工作线程、同一半径、同一几何版本下，已经验证的绕行路径可以供附近单位接入。每个目标区域最多保存四条走廊，最多保存 256 个目标区域，缓存有明确容量限制。

请求只有在起点能安全连接到走廊上距离不超过 8 m 的位置时才复用；新的入口和出口都重新检查。走廊中段保留已经验证的真实单位半径与几何版本，不把相近的队形落点强行改成相同终点。直接畅通的路径仍优先返回真实目标点。

缓存只复用搜索所得的几何路线，不承担窄口预约或单位运动调度。队列、局部避让和运动碰撞继续处理单位之间的相互影响。

### 连续地形安全与局部细化

`scripts/path_terrain_geometry.gd` 从工作线程的初始 `land`、`heights` 快照构造连续地形障碍：将不可通行区域合并为矩形，将相邻陆地单元高度差超过 0.8 m 的边界合并为水平或垂直线段。路线连接执行连续扫掠圆检查，覆盖离散采样可能漏掉的短暂岸线和悬崖角切入。被破坏的桥仍通过动态几何快照表示。

硬障碍继续使用原有的 `radius + 0.02 m` 间隙。连续地形检查使用实际单位半径；既有高度差阈值、坡道插值、中心路径高度采样和边缘通行检查继续保留。图中心之间有连接，也不足以绕过真实线段的安全验证。

地形障碍构建分为水区、垂直悬崖和水平悬崖三次线性网格扫描。地图边长为 N 时，构建时间为 O(N²)，每个工作线程按自己的地形快照构建一次。合并通常把输出规模压到地形边界数量；交错不可通行单元的最坏情况下，输出与存储仍可达 O(N²)。它将地形准备成本移到后台初始化，而不是为每个单位重新遍历地图。

若真实起终点站得下，却缺少可连接的整格图中心，或原图搜索无法连接，则只在对应端点附近按需加入半格候选点，范围为端点附近约 3 m。端点细化有去重记录，不把整张地图统一加密。新点继承当前地形、森林和建筑占用掩码，最终路线仍经过同样的扫掠检查。

### 几何变化与取消

建筑、森林和桥状态变化发布新的不可变几何快照。森林仍按分块版本更新，并使用节点占用引用计数，防止删除一棵树时错误开放被另一棵树覆盖的节点。

已有单位路径只在穿过改变区域时清除；远处新增或摧毁建筑不会让不相关的现有路径重新排队。无法确定改变范围时执行保守失效。后台缓存按几何版本失效，旧版本尚未执行的任务可以跳过；已开始的搜索正常结束，模拟通过版本和命令令牌丢弃过期结果。停止、死亡和换命令不会被旧结果重新启动。

## 压力场景与对照组

`tools/profile_navigation_throughput.gd` 使用真实后台模拟，不直接调用同步搜索代替任务排队。完整场景为 `handmade`、种子 `73026`、448 个单位与 32 座建筑，两队各 224 个单位、16 座建筑。建筑角色、混合单位角色、基地附近布局和间距来自 `main.setup_benchmark`；两队各自向敌基地发出一批移动命令。

本入口固定初始人口，不增援，以便单独比较寻路排队、算法和运动进展。正常生产、战斗增援及更大人口负载由 `tools/profile_final_pressure_cpu.gd` 等入口另外测量。

| 对照组 | 开关 | 模拟调度 | 工作线程搜索 |
|---|---|---|---|
| 完整旧版 | `--baseline` | 冻结旧模拟：2 条/tick、2 条在途 | 冻结单线程旧 Worker |
| 相同调度下的旧搜索 | `--baseline-worker-only` | 当前 16 条/tick、32 条在途、双线程池 | 冻结旧 Worker，保留旧实现每任务等待 |
| 当前算法关闭走廊缓存 | `--no-route-cache` | 当前双线程池 | 新简化、索引和安全检查，关闭走廊复用 |
| 新算法与走廊复用 | 无额外算法开关；使用调优前模拟 | 16 条/tick、32 条在途 | 新简化、索引、安全检查与走廊复用 |
| 最终默认方案 | 无额外算法开关 | 32 条/tick、32 条在途、双线程池 | 同上；缩短批量提交等待 |

冻结源码位于 `artifacts/free_navigation_performance_20261006/baseline/`。脚本在内存中移除冻结源码的 `class_name`，再注入工作线程工厂；旧源码的 `res://` 依赖保留。仅替换 Worker 的对照使用当前线程池源码和分派方式，以减少调度差异。也可用 `--baseline-sim=路径` 和 `--baseline-worker=路径` 指定冻结文件。

## 可复现调用

运行前检查其他 Codex 会话与系统进程是否正在执行 Godot、CPU 或渲染压力测试。各组按顺序执行，使用不同输出文件，并记录测量时的外部负载与源码哈希。下列命令从仓库根目录运行：

```bash
timeout 60s godot --headless --path . --script tools/profile_navigation_throughput.gd -- --units=448 --ticks=300 --realtime --max-wall-seconds=30 --baseline --output=artifacts/free_navigation_performance_20261006/final_original_448.json
timeout 60s godot --headless --path . --script tools/profile_navigation_throughput.gd -- --units=448 --ticks=300 --realtime --max-wall-seconds=30 --baseline-worker-only --baseline-sim=res://artifacts/free_navigation_performance_20261006/before_tuning/simulation.gd --output=artifacts/free_navigation_performance_20261006/final_original_pool_448.json
timeout 60s godot --headless --path . --script tools/profile_navigation_throughput.gd -- --units=448 --ticks=300 --realtime --max-wall-seconds=30 --no-route-cache --baseline-sim=res://artifacts/free_navigation_performance_20261006/before_tuning/simulation.gd --output=artifacts/free_navigation_performance_20261006/final_bounded_448.json
timeout 60s godot --headless --path . --script tools/profile_navigation_throughput.gd -- --units=448 --ticks=300 --realtime --max-wall-seconds=30 --baseline-sim=res://artifacts/free_navigation_performance_20261006/before_tuning/simulation.gd --output=artifacts/free_navigation_performance_20261006/final_cached_448.json
timeout 60s godot --headless --path . --script tools/profile_navigation_throughput.gd -- --units=448 --ticks=300 --realtime --max-wall-seconds=30 --output=artifacts/free_navigation_performance_20261006/final_tuned_repeat_448.json
```

`--realtime` 按单调墙钟安排 30 Hz 更新，300 个 tick 对应约 10 秒模拟窗口。慢 tick 会占用后续时间，脚本不改变时间倍率，也不利用 1 ms 的紧凑循环人为压缩整个模拟过程。达到指定 tick 数后，若仍有单位从未获得可见路径，会继续等待，直到全批完成、对局结束或 30 秒墙钟截止。截止后的未完成请求明确保留在报告中。

将以上命令的 `--units=448` 改为 `--units=48` 可进行同场景小队对照；人数按两队分配，48 总人数对应两队各 24 人。若要验证一次圈选 48 个单位的同批指令，使用下面的轻量回归入口：

```bash
timeout 60s godot --headless --path . --script tests/path_throughput_tests.gd -- --output=artifacts/free_navigation_performance_20261006/final_path_throughput_tests.json
```

该回归入口固定包含 48 人悬崖绕行、12 人断桥绕行、8 辆坦克绕过偏移建筑，以及一个停止在途请求的控制案例。它的 `--units` 不改变固定人数，`--ticks` 最多为 240，以保持正确性检查较轻。`--units=48 --ticks=300 --realtime` 的性能对照使用 profiler；一次选中 48 人的正确性使用固定回归场景。

## 指标与安全证据

这是 **headless 模拟与后台寻路测试**，不测 FPS、GPU、画面同步或选中路径绘制成本。报告中的“可见路径”表示单位实际获得非空剩余路径，可以交给选中路径显示层；它并非渲染帧完成时间。

| 字段 | 含义 |
|---|---|
| `first_visible_path_ms`、`last_visible_path_ms` | 从发出同批命令到首个、最后一个单位实际获得路径的墙钟时间；全批未完成时最后值为 null |
| `latest_observed_path_ms`、`observed_paths`、`missing_paths` | 截止前最晚观察到的路径及已完成/缺失人数，避免用部分批次冒充全批完成 |
| `first_collected_path_ms`、`last_collected_path_ms` | 后台结果被主线程收取的时间，独立于单位何时消费结果，不按最终几何版本删除早期记录 |
| `fixed_window_tick_ms`、`fixed_window` | 前 300 tick 的模拟耗时分位数，以及该窗口末尾的导航计数与运动进展；用同一窗口比较各组 |
| `tick_ms`、`worker_search_us`、`worker_queue_to_collect_ms` | 完整运行的 tick 耗时、后台搜索耗时、提交到收取的排队时间分布 |
| `navigation` | submitted、completed、discarded、队列、在途及 A*、走廊命中、连接检查、简化探测等计数；旧实现缺少的扩展计数不当作零性能成本 |
| `progress` | 移动超过 1 m、向目标净靠近超过 1 m、到达、暂时不可达和损失单位数 |
| `missing_unit_diagnostics` | 未得到路径单位的 ID、类型、起点、目标、当前位置、状态、静态站立合法性、首次结果是否为空，以及等待和请求状态 |
| `safety` | 首条非空工作线程路线的检查数、绕行数、空结果、unsafe 与具体冲突线段 |

模拟会把工作线程返回的路径数组直接交给单位，并在运动中执行 `pop_front` 或 `clear`。测量包装器必须先独立复制 `result.path`，才能保存从原始起点出发的完整路线；否则后续检查会把原始起点错误连接到被消费后的剩余路线。几何和地形证据也按任务快照保存，不能用结束时的实时单位或建筑状态反推早期路线。

安全 oracle 在计时窗口外工作：它使用每个任务自己的不可变 `job.geometry`，对建筑、废墟、矿点等执行独立的连续圆形扫掠检查，并使用初始工作线程地形快照按 0.25 m 间隔检查陆地、高度和半径边缘。unsafe 示例列出具体 leg、矩形或地形冲突点。该 oracle 与工作线程图缓存分开；完整连续地形边界的回归还由 `tests/any_angle_worker_tests.gd` 覆盖。

耗时分位数用于同机对照，不设易受机器负载影响的固定毫秒通过阈值。测试必须验证任务有界、停止令牌有效、每条返回路线安全，以及单位实际取得进展。外部 `timeout` 负责最终进程截止，模拟退出前显式关闭并等待工作线程结束。

## 最终结果

2026-10-06，Intel(R) Core(TM) Ultra 9 185H，Godot 4.6.2，同一修正后布局。旧视觉测试进程已按用户要求终止；各组串行执行。最终默认方案另做独立复测，启动前没有其他 Godot 进程。完整设备信息、源码哈希、各组 JSON 链接和回归结果保存在 `artifacts/free_navigation_performance_20261006/result_summary.json`。

| 方案 | 获得路径 | 全队出路耗时 | 后台任务平均耗时 | 300 tick 模拟 P95 | 严格路线检查：unsafe / checked |
|---|---:|---:|---:|---:|---:|
| 完整旧版 | 332/448 | 30 秒仍未完成 | 86.69 ms | 8.82 ms | 130 / 338 |
| 双线程旧搜索 | 448/448 | 27.95 秒 | 124.06 ms | 10.14 ms | 181 / 442 |
| 新搜索，不复用 | 448/448 | 1.59 秒 | 6.23 ms | 14.04 ms | 0 / 448 |
| 新搜索＋复用 | 448/448 | 1.25 秒 | 2.56 ms | 13.56 ms | 0 / 448 |
| 最终方案复测 | 448/448 | 1.26 秒 | 2.85 ms | 16.33 ms | 0 / 448 |

旧版截止时仍有 116 个单位没有可见路径，不能计算其完整批次的精确加速倍数。双线程旧搜索需要约 27.95 秒；最终默认复测约 1.26 秒，全批出路约快 22 倍。默认方案首次调优测量为 1.16 秒，独立复测为 1.26 秒；不把这种短时波动当作算法收益。

关闭路线复用后，新算法需约 1.59 秒；开启复用的 16 条/tick 对照约 1.25 秒，后台任务平均从 6.23 ms 降至 2.56 ms。新算法对照的 A* 搜索计数为 667；复用对照为 300，另复用 655 次走廊。后台平均统计包含不同数量的初次搜索和后续重规划，不能当成完全相同单条路线的精确微基准。

新实现让更多单位更早开始移动、碰撞和战斗，因此模拟 tick 的工作量高于仍在等待的旧版。该表不据此声称整体 FPS 提升。最终复测主线程寻路交换最大 0.39 ms，维持在原 0.75 ms 交换预算内；局部避让预算和物理时间倍率未降低。

严格 oracle 在旧版发现桥下水角等短暂地形切入；旧版基准因此按预期返回失败状态，日志没有脚本错误。新算法和复用方案均为 448 条有效首批路线、0 条冲突。不能把旧版“生成路径”视为“每条都可以实际执行”。

十组最终专项回归全部通过，共 1,854 项：1286 任意角度、桶扫描、缓存及连续地形检查；74 后台预算；19 局部几何失效；19 批量/断桥/车辆/取消；8 Debug 放置；20 脚本与原生让路；70 导航规则；152 自由移动；189 游戏规则；17 渲染与模拟并行。严格检查日志未发现 SCRIPT ERROR、资源泄漏或引擎错误；本轮没有宣称整个仓库测试套件已全部执行。

16 条/tick 对照的模拟冻结于 `artifacts/free_navigation_performance_20261006/before_tuning/simulation.gd`。复现该三组时，在上面的相应命令中加入 `--baseline-sim=res://artifacts/free_navigation_performance_20261006/before_tuning/simulation.gd`；最终默认使用当前源码和 32 条/tick。原版两组仍使用 `baseline/path_worker.gd`；完整原版另使用 `baseline/simulation.gd`。

默认方案另运行 40 秒墙钟：模拟推进 40.00 秒，期间记录 3,006 个结果，独立检查 2,971 条非空路线（包括后续重规划），0 条冲突；幸存的 383 个单位均移动超过 1 m，其中 382 个向目标净靠近超过 1 m，另 65 个在对战中损失。窄桥上的实体拥堵和交战仍存在，此测试没有要求双方全部穿过对方部队并到达基地。完整证据为 `final_bridge_40s.json`。使用 profiler 的 `--ticks=1200 --realtime --max-wall-seconds=41 --all-route-safety` 复现。
