# 即时响应导航优化（2026-10-07）

本轮优先缩短玩家下令后开始转向／移动的等待，保留连续坐标与任意角度移动。完整路径仍由后台 A* 生成，等待期间先做经过实际碰撞检查的短步；结果返回后重新校验接入，不能接入时重排。连续移动不再因起点漂移反复取消同一个后台请求。受阻短步有100毫秒错峰重试，同步规则测试保留原预算等待。

己方普通地面单位之间允许受限重叠：步兵约0.06格，车辆最多0.12格，混合体型取较小限额。敌军、坚守、建筑、岸线、悬崖和其他静态障碍保留原判定。圆形静态半径、速度和到达容差没有缩减或放宽。

增加独立5×5保守平地掩码，覆盖半径≤1.99的车辆；原生、脚本和worker共享该安全信息，复杂地形仍执行详细检查。铁路仍先于普通地面导航处理：所属玩家、连通限制、铁路专用车辆及2倍速度保持；离轨单位不再仅因地图存在铁路就关闭原生加速。铁路目标反向BFS及中心路线净空验证共享缓存，铁路／静态几何变化失效，真实起点每次独立校验。

## 测量

以下是本机无渲染、固定30Hz但压缩执行的模拟。墙钟响应从issue()开始计，到第一次观察到转向或位移；不包含真实输入事件、等待下一帧、渲染和上屏时间。不能换算FPS或当作玩家实机延迟保证。A/B仅切换即时启动和重叠开关，宽平地掩码及铁路优化在两组均开启。

| 场景 | 关闭即时启动的对照组：全员响应 | 开启后：全员响应 | 开启后模拟tick P95 |
| --- | ---: | ---: | ---: |
| 256步兵，开阔地 | 159.9ms，第18tick | 25.8ms，第1tick | 19.25ms |
| 256步兵，6格狭口入口 | 252.2ms，第26tick | 24.9ms，第1tick | 18.03ms |
| 512步兵，开阔地 | 30tick内未全部响应 | 51.5ms，第1tick | 34.92ms |
| 96步兵／坦克混编，8格狭口入口 | 87.9ms，第25tick | 8.6ms，第1tick（48位移、96转向） | 6.18ms |

单独完整通行：96混编全部通过8格口并完成原命令，88.03模拟秒，零静态穿越、HP不变、最大32在途；tick P95约5.96ms。与历史138秒样本的布局不同，不计算跨样本加速比例。

256列车密集共享轨道的专项中，缓存／邻居检查调整前后，命令处理约93→38ms，全员首tick响应墙钟约290→98ms，tick P95约213→108ms。该极端布局有大量同轨重叠，仍然较重，不能宣称铁路压力下已满足30或60FPS。

立即移动会增加当前帧工作：512步兵P95由等待状态对照的16.69ms增加到34.92ms。本轮改善的是启动响应，不能据此声称整体模拟耗时或FPS同比改善。

## 验证与限制

最终专项通过：即时响应102项、铁路响应／缓存517项、原铁路规则61项、原生几何9372项、路径预算74项、局部几何失效19项、路线接入12项、实际到达容差完成26项；宽掩码75810个检查／格点通过。较早阶段另通过原生／脚本完整tick6002项，最终两个helper收紧由针对性测试覆盖。

旧navigation_tests在修改前源码与当前源码下均为37通过、相同6失败及过期rivet_harvester引用错误。旧free_navigation_tests仍含旧尺寸和0.32到达阈值：当前r=1的既有容差是0.4；即时短步改变最终步长相位，引出额外4项过严阈值断言，真实12条路线均已完成并在既有0.4范围内，专门26项验证通过。本轮没有放宽到达容差，也没有将旧套件标为全通过。

测试前检查其他Godot进程，并与“完善RTS阵营与玩法系统”交换独占窗口，所有压力场景串行；最终压力记录包含源码／原生库SHA，运行期间未变。另一会话的玩法、UI和单位扩展改动已保留。
