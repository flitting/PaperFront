# 步兵单兵 / 小队视觉比较

运行独立 demo（不经过游戏主菜单）：

```bash
./demos/run_infantry_squad_demo.sh
```

重新生成 14 张 1920×1080 实机截图：

```bash
./demos/run_infantry_squad_demo.sh --capture
```

需要带 GPU 显示的 Godot 4.6.2；截图输出 `artifacts/squad_comparison_20261009/`。`gallery.html` 为完整原图索引，`contact_sheet.jpg` 为总览，`manifest.json` 记录渲染设备、人数、视角和保存结果。截图未使用 AI 生成。

按 N 切换开阔地、街巷、交火伤亡、密集集结，V 切换俯视、斜视、局部近景，4/5/6 切换编制，R 重置。左键选择对象，右键移动：左侧每次指挥一名士兵，右侧指挥整队，空格对所选编号附近施加距离衰减的范围伤害，Esc 退出。伤员仍移动，死亡成员留下独立倒地图形且不接受移动。

两侧均为相同的正典步枪兵，直接调用主游戏 `PaperWorld._card`，使用相同原图、切割轮廓、玩家色材质与 0.99×1.08 卡面尺寸。建筑来自主游戏 `VolumeModels.create_model`。场地及队伍 UI 是专为比较搭建的原型；单兵一侧的标识也为比较展示，不代表逐像素复刻现有 HUD。

## 视觉判断

5 人可作为首选编制：60 人从 60 个操控对象变成 12 个队伍，既保留人群规模，也让队与队之间出现明显空隙。4 人更疏朗但标记较多，6 人队伍更少但近景遮挡更明显。截图观察支持这个方向，尚未经玩家操作实验。

- 开阔地：小队比均匀散开的单兵更容易识别边界和部署方向。宜用松散交错站位，避免所有人重叠在一个点。
- 街巷：小队应收窄为错列纵队；若强行保留宽阵型，人员和队伍边界会挤在建筑、相邻队伍之间。原型给街道预置了窄队形，正式实现需要通道宽度感知和动态切换。
- 伤亡：保留逐人血量与尸体；队伍标签从 5/5 降为 4/5，选中显示成员血条。只显示汇总总血量会掩盖“满员但受伤”和“少人但健康”的区别。
- 远景：小队之间的空隙比单人的美术细节更有效。极远处应只保留队伍图标和人数；当前图片仍保留了人物及细标识，标签在远景变小，说明需要正式的屏幕像素阈值和信息层级。
- 同时显示所有队伍编号仍会形成文字噪声，正式版建议默认只显示类型图标/人数，悬停显示编号，选中显示详细成员血条。边界统一采用所属势力/玩家色，选中时用加粗区分；不要用大面积填充地面色块遮住纸片模型。

## 公平比较和验证范围

默认两侧初始各 60 人（12×5）；密集集结各 120 人（24×5）。4 人、6 人截图仍是每侧 60 人，分别为 15 队和 10 队。各成对场景使用同一相机、环境、兵种、模型大小和阵营色。局部近景只显示部分成员，总人数仍记在抬头中。

伤亡场景对两侧前 5 名成员依序施加相同的 110/65/35/0/85 伤害，得到 0/35/65/100/15 HP，每侧均存活 59 人。这是独立伤害与 UI 的受控演示，不是同一爆炸落点的战术平衡比较。交火画面为预置射击姿态和弹道线，不含自动寻敌/战斗 AI。

自动截图前另验证 4/5/6 人编制下的单人受伤不影响其他成员、独立死亡、右键整队命令、活人位移及死者不移动。保存清单检查了全部 14 张图片的成功状态、1920×1080 分辨率、两侧人数一致与伤亡人数一致；所有缩略图已复核，街巷斜视与伤亡近景另做原图复核。

独立演示未接入正式生产、寻路、碰撞、驻军、运输、补员、存档或 AI；移动使用直接插值，仅用于确认小队操控和画面关系。视觉相同人数意味着仍需绘制相同人数，不能据此宣称性能提升。实际群体寻路性能也未测量。
